问题引入与背景
问题描述
计算机中常用像素值序列 {p1, p2, ..., pn} 来表示图像，其中每个像素值 pi 都是 0 到 255 之间的整数。
变长编码压缩机制
为了节省空间，需要将像素序列分割成若干个连续的段。对于每一个分段：
• 段长度 l[i] <= 256（存储长度需要 8 位）。
• 段位宽 b[i] <= 8（存储位宽需要 3 位）。
• 每一段的段头信息开销为固定的 11 位（8位表示长度 + 3位表示位宽）。
优化目标
目标是最小化存储总空间，即：所有段的（段长度 × 段位宽 + 11位段头开销）之和的最小值。
--- Slide 4 ---
步骤一：刻画最优解结构
—— 证明问题具备最优子结构性质
核心定理：原问题的最优解包含子问题的最优解。
• 数学证明：
设 {p_1, p_2, ..., p_n} 的一个最优分段为 S_1, S_2, ..., S_m。最后一段为 S_m = {p_{n-l[m]+1}, ..., p_n}。
如果我们将最后这一段切除，那么剩余的前缀像素序列的分段方式，也必须是该前缀序列的最优分段方案。
若不然，假设该前缀序列存在一个更优分段方式，其开销为 W < 求和_{i=1}^{m-1} (l[i] × b[i] + 11)。
那我们将这个更省空间的分段与最后一段合并，就会得到一个总空间开销更小的新方案。这与我们假设原方案已是最优相矛盾。
因此，图像压缩原问题的最优解包含了子问题的最优解，问题满足最优子结构性质。
--- Slide 5 ---
步骤二：递归定义最优解值
—— 写出递归递推式 (状态转移方程)
状态定义
定义 s[i] 为前 i 个像素（即 p1 到 pi）进行最优分段所需的最小存储位数。
递归递推式设计
假设当前子问题最优解中，最后一段的长度为 k（其中 k 大于等于 1，且不超过像素数 i 和 256 的最小值）：
• 该段像素的最大位宽：b_{最大值}(i-k+1, i) = 最大值_{i-k+1 <= r <= i} { length(p_r) }
其中每个像素 p 所需的二进制位数计算方式为：log2(p + 1) 向上取整。
• 此时的 s[i] 即为：前 i-k 个像素的最优存储位数，加上最后这一段的存储开销（k 乘以最大位宽，再加上 11 位段头）。
递归递推式 (状态转移方程)
递推公式：s[i] = 最小化 { s[i-k] + k × (该段最大位宽) } + 11，其中 k 的取值范围是 1 到 i 与 256 的最小值。
• 边界条件：s[0] = 0。
--- Slide 6 ---
步骤三：自底向上计算最优值
—— 填表、循环遍历所有子问题，算出全部 dp 值
• 填表思路：
构建一维状态数组 s[0..n]。自底向上从小到大计算，在计算每个位置时，通过遍历最后一段可能的所有长度 j，计算并填入最优值。
• 循环逻辑：
• 外层循环 i：遍历所有的前缀子问题大小，即求解 s[1], s[2], ..., s[n]。
• 内层循环 j：遍历所有可能的最优分段长度 j（从 1 到最大限制），计算并取其最小值。
• 状态表变化：
每次计算 s[i] 时，其值仅依赖于先前已经计算并保存好的较小子问题最优值 s[i-j]。
--- Slide 7 ---
手算递推实例（一）：计算 i = 1 到 3

第 1 步：i = 1
• 处理像素：p[1] = 10（初始位宽 4位）
• 默认划分（最后一段长度为 1）：
    - 划分情况：║ [ 10 ]
    - 空间开销：s[0] + 1 * 4 = 0 + 4 = 4位
• 决策与结算：
    - 唯一方案，直接采纳
    - 加上段头开销 11位：s[1] = 4 + 11 = 15位
    - 记录最优最后段长 l[1] = 1，位深 b[1] = 4

第 2 步：i = 2
• 处理像素：p[2] = 12（初始位宽 4位）
• 试探 j = 1（第2个像素单独划为一段）：
    - 划分情况：[ 10 ] ║ [ 12 ]
    - 空间开销：s[1] + 1 * 4 = 15 + 4 = 19位
• 试探 j = 2（前2个像素合并为一段）：
    - 划分情况：║ [ 10, 12 ]
    - 空间开销：s[0] + 2 * 4 = 0 + 8 = 8位
• 决策与结算：
    - 因 8 < 19，选择合并方案 (j=2)
    - 加上段头开销 11位：s[2] = 8 + 11 = 19位
    - 记录最优最后段长 l[2] = 2，位深 b[2] = 4

第 3 步：i = 3
• 处理像素：p[3] = 15（初始位宽 4位）
• 试探 j = 1（第3个像素单独划为一段）：
    - 划分情况：[ 10, 12 ] ║ [ 15 ]
    - 空间开销：s[2] + 1 * 4 = 19 + 4 = 23位
• 试探 j = 2（最后两个像素合并为一段）：
    - 划分情况：[ 10 ] ║ [ 12, 15 ]
    - 空间开销：s[1] + 2 * 4 = 15 + 8 = 23位
• 试探 j = 3（前3个像素全部合并）：
    - 划分情况：║ [ 10, 12, 15 ]
    - 空间开销：s[0] + 3 * 4 = 0 + 12 = 12位
• 决策与结算：
    - 因 12 < 23，选择全合并方案 (j=3)
    - 加上段头开销 11位：s[3] = 12 + 11 = 23位
    - 记录最优最后段长 l[3] = 3，位深 b[3] = 4
--- Slide 8 ---
手算递推实例（二）：关键决策 i = 4 与 i = 5

第 4 步：i = 4 (大数单飞)
• 处理像素：p[4] = 255（初始位宽 8位）
• 试探 j = 1（大数 255 单独划为一段）：
    - 划分情况：[ 10, 12, 15 ] ║ [ 255 ]
    - 空间开销：s[3] + 1 * 8 = 23 + 8 = 31位
• 试探 j = 2 到 4（尝试将大数并入）：
    - j = 2：s[2] + 2 * 8 = 19 + 16 = 35位
    - j = 3：s[1] + 3 * 8 = 15 + 24 = 39位
    - j = 4：s[0] + 4 * 8 = 0 + 32 = 32位
• 决策与结算：
    - 因 31 为各方案最小值，选择 j=1 (单飞)
    - 加上段头开销 11位：s[4] = 31 + 11 = 42位
    - 记录最优最后段长 l[4] = 1，位深 b[4] = 8

第 5 步：i = 5 (重新合并)
• 处理像素：p[5] = 1（初始位宽 1位）
• 试探 j = 1（第5个像素单独划为一段）：
    - 划分情况：[10,12,15] [255] ║ [1]
    - 空间开销：s[4] + 1 * 1 = 42 + 1 = 43位
• 试探 j = 2（大数 255 与 1 合并）：
    - 划分情况：[ 10, 12, 15 ] ║ [ 255, 1 ]
    - 空间开销：s[3] + 2 * 8 = 23 + 16 = 39位
• 试探 j = 3 到 5：
    - j = 3：s[2] + 3 * 8 = 19 + 24 = 43位
    - j = 5：s[0] + 5 * 8 = 0 + 40 = 40位
• 决策与结算：
    - 因 39 最优，选择合并方案 (j=2)
    - 加上段头开销 11位：s[5] = 39 + 11 = 50位
    - 记录最优最后段长 l[5] = 2，位深 b[5] = 8

前 5 像素最优解总结
• 最终最优分段方案：
    - 根据前 5 个像素回溯，最终确定划分：
• 第 1 分段 [像素 1 到 3]：
    - 包含数值：[ 10, 12, 15 ]（位宽 4位）
    - 存储空间：3 * 4 + 11 = 23位
• 第 2 分段 [像素 4 到 5]：
    - 包含数值：[ 255, 1 ]（位宽 8位）
    - 存储空间：2 * 8 + 11 = 27位
• 总存储开销：
    - 两段总空间合计为：23 + 27 = 50位
    - (因为数据量小导致头部开销占比大；在大规模像素下，变长压缩优势将极其明显)

步骤三：自底向上计算最优值 (原教材代码)
—— 自底向上的动态规划实现
// 计算整数 i 的二进制位数
int length(int i) {
    int k = 1; i = i / 2;
    while (i > 0) { k++; i = i / 2; }
    return k;
}

// 自底向上填表计算最优值 s[i]
void Compress(int n, int p[], int s[], int l[], int b[]) {
    int Lmax = 256, header = 11;
    s[0] = 0; // 填表边界
    for(int i = 1; i <= n; i++) { // 循环遍历所有子问题规模 i
        b[i] = length(p[i]); 
        int bmax = b[i];
        s[i] = s[i-1] + bmax;
        l[i] = 1;
        for(int j = 2; j <= i && j <= Lmax; j++) { // 遍历可能的最后一段长度 j
            if(bmax < b[i-j+1]) bmax = b[i-j+1];
            if(s[i] > s[i-j] + j*bmax) {
                s[i] = s[i-j] + jbmax; // 填入更小开销
                l[i] = j;
            }
        }
        s[i] += header; // 加上固定头部开销，得到完整最优值并存入 s[i]
    }
}

步骤三拓展：教材代码 Bug 深度剖析
—— 自底向上计算时的状态存储缺陷
• 教材代码的严重缺陷：
在 Compress 中，b[i] 数组仅在外层循环初次赋值为单个像素位宽。而在内层循环优化时，选定的最优划分段的实际最大位宽 bmax 可能变大。
原代码漏掉了更新 b[i] = bmax; 的步骤。
• 产生的后果：
虽然最优值表 s[i] 计算正确，但是在第四步调用 Output 回溯构造解时，由于 b[s[j]] 拿到的并不是整段的最优最大位宽，导致构造的最优解分段数据位宽全错！
• 我的修正：
在选择更优解的 if 块中加入 b[i] = bmax; 状态更新。

步骤四：构造完整最优解
—— 回溯记录路径，输出具体方案
设计提示：
“ 设计提示：如果我们在实际工程应用中只需要最值（即只需要知道最小存储位是多少，不需要知道具体如何划分），可以省略第 4 步，仅保留前三步计算出的 s[n]。若需要输出具体的图像分段方案，则必须进行第 4 步。 ”
• 构造方法：
通过递归回溯已经记录的每个位置的最优段长度，依次推导出每个分段的划分边界，最终输出具体方案。

步骤四：构造完整最优解 (代码实现)
—— 回溯记录路径，输出具体方案
// 递归回溯记录路径
void Traceback(int n, int& i, int s[], int l[]) {
    if (n == 0) return;
    Traceback(n - l[n], i, s, l);
    s[i++] = n - l[n]; // 回溯记录每一段的起始像素下标
}

// 转换并输出具体方案
void Output(int s[], int l[], int b[], int n) {
    cout << "The optimal value is " << s[n] << endl;
    int m = 0; Traceback(n, m, s, l); s[m] = n;
    cout << "Decompose into " << m << " segments" << endl;
    for (int j = 1; j <= m; j++) {
        l[j] = l[s[j]];
        b[j] = b[s[j]]; // 完美依赖于修复后的 b 数组
    }
    for (int j = 1; j <= m; j++)
        cout << "Segment " << j << ": Length = " << l[j] << ", BitWidth = " << b[j] << endl;
}
--- Slide 13 ---
算法复杂度与空间分析
时间复杂度
• 外层循环：执行 n 次。
• 内层循环：最多迭代 最小值{i, 256} 次。由于段长上限 L_{最大值} = 256 是常数，内层迭代次数 O(1)。
• 总时间复杂度：为 O(n)（线性时间复杂度），在大数据量下优势明显。
空间复杂度
• 使用了一维数组 s、l、b，空间均与 n 成线性关系。
• 总空间复杂度：为 O(n)。
--- Slide 14 ---
总结与启发
常数上限优化：通过对最大段长度 L_{最大值} = 256（8位表示）的物理硬限制，将本质是 O(n^2) 的动态规划算法成功优化至 O(n)。
重叠子问题高效性：自底向上的查表计算有效避免了分段组合的指数级回溯开销。
严谨的开发规范：在算法到代码落地的转换中，极细微的状态更新缺失（如 b[i] = bmax）都会导致解构造失效。在结对编程 and 代码 Review 中需要格外警惕类似缺陷。
